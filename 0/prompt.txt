### Part 2 — CaptureBuffer (plan A2)

Per the plan: capture is scoped to N whole sound evaluations, not a wall-clock window, because the raw ray stream has no wall-clock timestamp and a time-window would slice through the middle of one sound's reflection tree.

Create debug/CaptureBuffer.java:
- A CapturedRay record: start Vec3d, end Vec3d, color int, soundEventId int, bounceIndex int, material (nullable Material, from Part 1's plumbing).
- startCapture(int events) — events=-1 means open-ended (capped only by the ring buffer size, see below); resets/clears any prior capture.
- stopCapture() — ends capture immediately (remaining=0).
- isCapturing() — true while remaining != 0.
- onSoundEvalStart() / onSoundEvalEnd() — call sites are Engine.evalEnv(...) (search for it; call onSoundEvalStart() at entry, onSoundEvalEnd() at return — onSoundEvalEnd() decrements remaining if remaining > 0, no-op if remaining == -1 (open-ended) or already 0).
- offer(CapturedRay) — appends only while isCapturing(); backed by debug.math.RingBuffer with plan B1's larger cap (MAX_CAPTURED_SEGMENTS = 16384, drop-oldest). The FIRST time a single capture session actually hits this cap, trigger a one-time warning (expose it as e.g. a Runnable/Consumer<String> callback or a simple 'boolean consumeTruncationWarning()' the caller can poll — do not directly call Minecraft chat/actionbar APIs from this class, keep it Minecraft-light so it stays easy to unit test; the actual actionbar display can be wired by whoever calls offer(), which will be BounceRayLayer/RayLineLayer in Part 3).
- asCapturedList() — read-only snapshot in insertion order (delegate to RingBuffer.asList()).
